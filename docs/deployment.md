# Deployment notes

Frontend on **Vercel or Netlify**; backend + PostgreSQL on **Render or Railway**.

## Backend (Render)

1. Push the repo, then in Render choose **New → Blueprint** and select `render.yaml`. It creates the
   `samvaad-api` web service (root `backend/`) and the `samvaad-db` PostgreSQL database.
2. Set the secret env vars when prompted:
   - `PHONE_ENCRYPTION_KEY` — **required**; generate with
     `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
     Keep it stable: changing it makes stored call-back numbers unreadable.
   - `CORS_ORIGINS` — your frontend URL, e.g. `https://samvaad.vercel.app`.
   - `ANTHROPIC_API_KEY` and `LLM_MODE=anthropic` — optional. Without them the app runs in mock mode.
   - `ADMIN_PIN` / `COUNSELLOR_PIN` are generated by Render; copy them from the dashboard.
3. Each deploy runs `alembic upgrade head` before starting. **Seed once** from the Render shell:
   `python -m seed.seed --all && python -m seed.simulate_sessions`.
   Re-running `seed.seed` without `--all` replaces only the evidence tables and keeps sessions.
4. Run **one worker**. Live-chat rooms are held in memory; the 3-second polling fallback works across
   instances, but instant WebSocket delivery needs all clients on the same process. To scale, add Redis pub/sub
   in `escalation.Rooms`.
5. Health check: `GET /api/health`.

**Railway:** create a PostgreSQL plugin and a service from `backend/` with the same start command and env vars.
`DATABASE_URL` values starting `postgres://` are normalised to `postgresql+psycopg://` automatically.

## Frontend (Vercel or Netlify)

- Root directory: `frontend/`. Build `npm run build`, output `dist/`.
- Env var: `VITE_API_BASE_URL=https://<your-render-service>.onrender.com`.
- SPA routing: `frontend/vercel.json` (Vercel) and `frontend/public/_redirects` (Netlify) send every route to `index.html`,
  so QR links such as `/summary/<id>` open directly.
- The browser connects to `wss://<backend>/ws/...` for live chat; Render supports WebSockets on web services.

## Before a public pilot

- Replace demo PIN auth with real identity for counsellors and admins.
- Import organiser or official data with `--status verified`. The admin data-quality panel shows what is still demo.
- Have Kannada strings (`kn.json`, mock templates, escalation summaries) reviewed by a native speaker.
- Write a privacy notice and retention policy for call-back numbers (DPDP Act). Delete numbers after the call
  using **Delete number** in the console.
- Run Lighthouse (mobile, Lite mode) against the deployed build. The target is ≥ 80.
